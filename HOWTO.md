## What quickjobs is

quickjobs scrapes employer ATS boards directly (Greenhouse, Lever, Ashby, Workday, Oracle HCM, and others configured in your company list), applies your personal filters from the profile, merges pipeline state (applied, screen, pass), and generates a static HTML job board you open in a browser. It is not a live job-aggregator feed: each run fetches current postings from configured employers and rebuilds the board from scratch (with snapshot merge for continuity).

## Key files

| Field | Your current setting | Meaning |

## Two command families

### 1. Remote scrape workflow (`quickjobs` bash CLI)

Runs from anywhere on your Mac. Handles portable builds, sync to wulf, scrape, status, and hub tooling.

```bash
quickjobs portable          # build portable zip
quickjobs sync              # validate + push code, bins, runtime to wulf
quickjobs run               # sync + full scrape on wulf
quickjobs run --only netflix,openai
quickjobs stop              # stop active scrape
quickjobs resume            # resume from checkpoint
quickjobs restart           # stop then resume
quickjobs results           # tail running scrape or last summary
quickjobs status            # snapshot: run state + log tail
quickjobs shard             # Workday Playwright shard
quickjobs deploy            # first-time server setup
quickjobs hubs <subcommand> # hub convert / discover / probe (different from employer discover below)
quickjobs draft --dry-run   # next tenths GitHub draft (Mac gh auth; agents must not run create)
quickjobs draft             # create draft release at next version (e.g. 0.0.9 → 0.1.0)

# Chain commands (comma or space; extra args go to the last step):
quickjobs portable,sync,run
quickjobs sync,run
quickjobs sync,run --only akamai,netflix
quickjobs sync,restart
```

### 2. Dev-machine discover / validate (`discover_cli.py`)

Runs from the repo on your Mac only. Does not touch wulf unless you follow with `quickjobs sync`.

```bash
cd ~/ws/github/quickjobs

~/.v/bin/python scripts/discover/discover_cli.py validate
~/.v/bin/python scripts/discover/discover_cli.py discover dice
~/.v/bin/python scripts/discover/discover_cli.py discover-sync dice --dry-run
~/.v/bin/python scripts/discover/discover_cli.py dedup
```

The same `validate`, `discover`, and `discover-sync` commands also work via `quickjobs.david.py` (it delegates to `discover_cli.py`). `dedup` is only available through `discover_cli.py`.

Note: the bash `quickjobs` wrapper on PATH does not yet expose `discover`, `discover-sync`, `validate`, or `dedup` as subcommands. Use the Python forms above from the repo root.

## Daily and routine workflow

### Before editing config

Always validate first:

```bash
cd ~/ws/github/quickjobs
~/.v/bin/python scripts/discover/discover_cli.py validate
```

Fix any JSON or duplicate-id errors before syncing.

### Refresh the board (typical)

One chained command builds portable zip (optional), syncs, and runs a full scrape:

```bash
quickjobs portable,sync,run
```

Or without portable:

```bash
quickjobs sync,run
```

### After the scrape

1. Check progress or last run:

```bash
quickjobs results
# or
quickjobs status
```

2. Open the board. On wulf the published HTML is at `/mnt/Uploads/html/job-search-david.html`. On your Mac the dev copy is at `~/Downloads/jobs/job-search-david.html`.

3. If you edited pipeline status (applied/screen/pass) in the browser, sync runtime back to wulf:

```bash
quickjobs sync
```

### Pipeline linking (browser)

The board uses the File System Access API to read/write `~/.job_search/quickjobs/david/job-board-runtime.json`. Link that file once per browser profile (Chrome or Edge). After status changes, run `quickjobs sync` so wulf gets the updated sidecar.

For local `file://` HTML only, you can use the pipeline autosave server (port 8765 — see [Remote host](#remote-host-wulf)).

### Mid-run code fix

If a scrape is running and you need to push code changes:

```bash
quickjobs sync,restart
```

## Viewing the board and rebuilding HTML

### Open the HTML board

```bash
open ~/Downloads/jobs/job-search-david.html
```

The file is large (~64 MB). Do not grep or read it wholesale in a terminal.

### Rebuild HTML from snapshot (no scrape)

When a snapshot exists but you want fresh HTML without re-scraping all companies:

```bash
quickjobs portable,sync,rebuild
```

Or if code is already on wulf:

```bash
quickjobs sync,rebuild
```

`rebuild` syncs code/config first (like `run`), then runs `rebuild-snapshot` on wulf. Optional flags pass through: `--recompute-matches`, `--verify-urls`.

Mac-only (local snapshot in `~/.job_search/quickjobs/david/`; stale job data if wulf scraped more recently):

```bash
quickjobs rebuild --local
```

On wulf directly (SSH):

```bash
quickjobs-run --rebuild
```

Optional: recompute match tiers from snapshot JD text:

```bash
quickjobs rebuild --recompute-matches
```

### Pull HTML from wulf to Mac

Default sync does not push HTML from Mac to wulf or pull it back. After a remote scrape, copy manually or use:

```bash
QUICKJOBS_SYNC_PUSH_DATA=1 quickjobs sync
```

to push dev HTML/snapshot/digest/`json_sidecars/` to wulf (unusual; normally wulf is the publisher).

### Lazy board JSON sidecars and compression

Each board write also creates `json_sidecars/` next to the HTML:

- `lazy_board_index.json`
- `lazy_board_payload.json`
- `lazy_board_descriptions.json`
- `lazy_board_deferred.json`

plus `.gz` (and `.br` when the `brotli` package is installed) next to each file.

On Synology HTTPS, enable gzip and/or brotli for `application/json` (and static
`.gz`/`.br` if your nginx uses `gzip_static` / `brotli_static`). The board page
`fetch`es these files; portable `file://` opens fall back to embedded JSON so
they keep working without a server.

## Employer discovery pipeline

### Purpose

Discovery finds new employers to add to `quickjobs.david.base.json`. It catalogs companies and their ATS endpoints over time. It does not track live job listings for the board.

Think of it as: mine job boards for company names → fingerprint their ATS once → review candidates → merge high-confidence entries into base.json → sync → scrape.

### Sources

| Source | Command | What it mines | Notes |
|--------|---------|---------------|-------|
| Dice | `discover dice` | Dice.com MCP (`search_jobs`) | Widest net when `posted_date` is omitted; fingerprints cached |
| HN | `discover hn` | Monthly "Who is hiring?" threads via Algolia API | Direct employers, often include salary and careers URL |
| Built In | `discover builtin` | `builtin.com` remote category pages (robots-allowed pagination) | Parses HTML cards; ATS resolved by name |
| All three | `discover all` | Runs dice, then hn, then builtin | Sequential |

Sources not used for discovery (not viable for unattended catalog mining):

- Wellfound: requires browser session / IP gates; not suitable for scheduled catalog runs
- Y Combinator / Work at a Startup: no stable open API for employer cataloging at this profile's scale

### Step 1: Run discovery (does not modify base.json)

```bash
cd ~/ws/github/quickjobs
~/.v/bin/python scripts/discover/discover_cli.py discover dice
~/.v/bin/python scripts/discover/discover_cli.py discover hn
~/.v/bin/python scripts/discover/discover_cli.py discover builtin
# or all at once:
~/.v/bin/python scripts/discover/discover_cli.py discover all
```

Defaults per source (widest net, API-only fingerprint, no Playwright):

| Source | Default flags |
|--------|---------------|
| dice | `--fingerprint api` (no `posted_date` = widest Dice window) |
| hn | `--fingerprint api` |
| builtin | `--fingerprint api --pages 5` |

Forward extra miner flags after `--`:

```bash
~/.v/bin/python scripts/discover/discover_cli.py discover dice -- --max-fingerprint 40 --max-pages 3
```

Outputs land in `~/ws/scriptdir/output/`:

- Persistent catalogs: `dice-employer-catalog.json`, `hn-employer-catalog.json`, `builtin-employer-catalog.json`
- Per-run reports: `<source>-new-candidates-<date>.json` and `.md`

Catalog behavior:

- Persistent across runs; posting counts do not inflate on reruns (deduped by source job id / Dice GUID)
- ATS fingerprint runs once per new employer; cached thereafter
- Dice reruns re-query the API but only fingerprint employers not yet in the catalog
- Agencies are kept in the catalog with `is_agency: true` but excluded from sync candidates

### Step 2: Preview sync (dry run)

```bash
~/.v/bin/python scripts/discover/discover_cli.py discover-sync dice --dry-run
~/.v/bin/python scripts/discover/discover_cli.py discover-sync all --dry-run --limit 10
```

### Step 3: Merge into base.json

```bash
~/.v/bin/python scripts/discover/discover_cli.py discover-sync dice
~/.v/bin/python scripts/discover/discover_cli.py discover-sync hn --limit 20
~/.v/bin/python scripts/discover/discover_cli.py discover-sync all
```

Candidate source: newest `<source>-new-candidates-*.json`, field `all_api_scrapable_direct_not_in_base`. Falls back to the persistent catalog if no report exists.

Conservative filters (default):

| Filter | Default | Override flag |
|--------|---------|---------------|
| API-scrapable ATS only | on | (no override; required) |
| `ats_confidence == high` | on | `--include-review` to allow `review` confidence |
| Not a staffing agency | on | `--include-agency` |
| Not already in base.json | on | `--include-in-base` |
| Salary floor | none | `--min-salary N` (annual USD) |
| Max adds per source | unlimited | `--limit N` |

Safety on write:

- Timestamped backup to `~/.numbered_backups/` before modifying `quickjobs.david.base.json`
- Post-write validation; restore instructions printed if validation fails

After a successful sync, propagate to wulf and scrape:

```bash
~/.v/bin/python scripts/discover/discover_cli.py validate
quickjobs sync,run
```

### Example cadence (weekly / monthly)

```bash
cd ~/ws/github/quickjobs

# Monday: Dice catalog refresh
~/.v/bin/python scripts/discover/discover_cli.py discover dice -- --max-fingerprint 40

# 7th of month: HN threads
~/.v/bin/python scripts/discover/discover_cli.py discover hn -- --threads 2 --max-fingerprint 40

# Tuesday: Built In
~/.v/bin/python scripts/discover/discover_cli.py discover builtin

# Preview adds, then merge
~/.v/bin/python scripts/discover/discover_cli.py discover-sync all --dry-run
~/.v/bin/python scripts/discover/discover_cli.py discover-sync all --limit 50

# Validate, sync, scrape new companies
~/.v/bin/python scripts/discover/discover_cli.py validate
quickjobs sync,run
```

To schedule discovery on your Mac, use `cron-exec` with absolute paths (example only — not installed by quickjobs):

```cron
15 7 * * 1 cron-exec /Users/deibhaid/.v/bin/python /Users/deibhaid/ws/github/quickjobs/scripts/dice/discover_dice_employers.py --max-fingerprint 40 --fingerprint api
```

Or invoke via discover CLI:

```cron
15 7 * * 1 cron-exec /Users/deibhaid/.v/bin/python /Users/deibhaid/ws/github/quickjobs/scripts/discover/discover_cli.py discover dice -- --max-fingerprint 40
```

### Discovery vs hub tooling

`quickjobs hubs discover` is a different tool: it deep-probes ATS paths on hub URLs already in your config. Employer discovery (`discover dice|hn|builtin`) mines external job boards for new company names. Both can feed new employers, but they use different scripts and outputs.

## Validation and duplicates

### Static validation

```bash
cd ~/ws/github/quickjobs
~/.v/bin/python scripts/discover/discover_cli.py validate
```

Checks:

- `quickjobs.david.base.json` — keywords, sections (no inline companies)
- `quickjobs.david.companies.json` — companies list, required ATS fields
- `quickjobs.david.profile.json` — valid JSON
- `quickjobs.david.py` — compiles
- Delegates to `validate-static-config` for tier keywords and core rules

Current company count (run validate to refresh): 1143 companies.

`quickjobs sync` runs the same static validation automatically unless you set `QUICKJOBS_SYNC_SKIP_VALIDATE=1`.

### Duplicate ATS keys

Some employers share a corporate ATS board (especially Oracle HCM `cx_1`, `cx_1001`, `cx_2001`). These are known pre-existing groups, not accidental copy-paste errors.

Report duplicates:

```bash
~/.v/bin/python scripts/discover/discover_cli.py validate --duplicates
~/.v/bin/python scripts/discover/discover_cli.py dedup
```

Both report 8 duplicate ATS groups in the current base.json. Neither modifies the file.

Fail validation on duplicates (strict CI-style check):

```bash
~/.v/bin/python scripts/discover/discover_cli.py validate --strict-duplicates
```

`dedup --apply` is not implemented. Review the report and merge manually if needed.

## Partial runs and exclusions

### One-off partial scrape

```bash
quickjobs run --only netflix,openai
quickjobs sync,run --only akamai,american-express,bny-mellon
```

Company ids are comma-separated on a single flag (no spaces inside the list).

### Exclude companies for one run

```bash
quickjobs run --exclude tesla,lockheed-martin
```

### Permanent exclusions (`company_ids_exclude`)

Edit `quickjobs.david.profile.json` → `company_ids_exclude` array. These companies are skipped on every run without passing `--exclude`. After editing, validate and sync:

```bash
~/.v/bin/python scripts/discover/discover_cli.py validate
quickjobs sync
```

## Backups

### Numbered rolling backups

Before `discover-sync` writes companies, rolling backups (7-day retention) are saved under:

```
~/.numbered_backups/Users/deibhaid/ws/github/quickjobs/quickjobs.david.base.json_<M.D.Y_H:MM:SS>
~/.numbered_backups/Users/deibhaid/ws/github/quickjobs/quickjobs.david.companies.json_<M.D.Y_H:MM:SS>
```

Snapshots older than 7 days are pruned automatically on each backup.

Restore if a bad merge occurs:

```bash
cp ~/.numbered_backups/Users/deibhaid/ws/github/quickjobs/quickjobs.david.base.json_<date>_<time> \
   ~/ws/github/quickjobs/quickjobs.david.base.json
~/.v/bin/python scripts/discover/discover_cli.py validate
quickjobs sync
```

See `~/.numbered_backups/INDEX.md` for the full backup index.

### Sync validation failure

If `discover-sync` fails post-write validation, it prints restore instructions. Do not sync to wulf until validation passes.

## Remote host (wulf)

### What sync pushes

1. Static code + JSON from repo (`rsync --delete` for listed files only)
2. `quickjobs-run`, `quickjobs-run-shard`, `quickjobs-raise-nofile` binaries
3. Runtime sidecar from `~/.job_search/quickjobs/david/job-board-runtime.json`
4. HTML / snapshot / digest only when `QUICKJOBS_SYNC_PUSH_DATA=1`

### Environment on wulf (`quickjobs-run`)

| Variable | Default on wulf | Meaning |
|----------|-----------------|---------|
| `QUICKJOBS_JOBS_DIR` | `/mnt/Uploads/html` | HTML output directory |
| `JOB_SEARCH_DIR` | same as jobs dir | Runtime sidecar root |
| `QUICKJOBS_VERIFY_ALL` | 1 | Verify job URLs after scrape |
| `QUICKJOBS_HTTP_WORKERS` | 16 | Parallel HTTP company pool |
| `QUICKJOBS_NO_REMOTE_SYNC` | 1 | Cron/run does not rsync back to Mac |

Transient files on wulf (not synced):

- `/tmp/quickjobs/david/cache/` — HTTP response cache
- `/tmp/quickjobs/<namespace>/scrape-checkpoint.jsonl` — resume checkpoint
- `~/ws/scriptdir/output/quickjobs-run.active` — active run pid/log pointer
- Scrape logs under `~/ws/scriptdir/output/quickjobs-reports/`

### Ports: 8765 vs 8768

| Port | Use |
|------|-----|
| 8765 | `quickjobs run --pipeline-server` — pipeline autosave for local `file://` HTML. Do not use for ad-hoc preview if this may conflict with an active pipeline server. |
| 8768 | Suggested port for ad-hoc `python -m http.server` HTML preview. Kill when done. |

Port 8765 is reserved for the pipeline autosave workflow, not general preview.

### Rebuild snapshot on wulf

```bash
quickjobs-run rebuild-snapshot
```

### Cron on wulf

Daily scrape is typically cron-driven on wulf with `QUICKJOBS_VERIFY_ALL=1` and `QUICKJOBS_NO_REMOTE_SYNC=1`. Use `quickjobs deploy` or `quickjobs-server/install-server-cron` for setup. Edit code on Mac and `quickjobs sync` rather than editing files directly on wulf.

## Troubleshooting

### Validation failed on sync

```bash
cd ~/ws/github/quickjobs
~/.v/bin/python scripts/discover/discover_cli.py validate
# or more detail:
~/.v/bin/python quickjobs.david.py validate-static-config --dir .
```

Fix JSON syntax, missing required ATS fields, or duplicate company ids. Then sync again.

### discover-sync reports 0 adds

Normal when candidates are already in base.json or filtered out by conservative rules. Run `discover <source>` first to refresh the catalog and dated report. Use `--dry-run` to see what would be skipped and why. If everything is already synced, 0 adds is expected.

### Long first run after bulk adds

Adding many companies via `discover-sync` increases scrape time linearly. Expect a longer `quickjobs run` on the first full scrape after a large merge. Use `--only new-company-id` to test one employer before a full run.

### Zero-yield companies

Some employers return no matching jobs after keyword/salary/location filters. The board can hide zero-yield sidebar entries (`profile.board_ui.hide_zero_yield_sidebar`). Job Sources then lists only employers with primary-board listing cards (not excluded/pass-only rows under Show Hidden). This is display-only; the company remains in base.json unless you remove it or add to `company_ids_exclude`.

### Dev board differs from wulf board

Expected if wulf scraped more recently than your local HTML. Fix: wait for cron, run `quickjobs sync,run`, or copy published HTML from wulf. Default sync does not pull remote HTML to Mac.

### Stale pipeline state

Canonical source is `~/.job_search/quickjobs/david/job-board-runtime.json`. The `~/Downloads/jobs/job-board-pipeline.json` mirror may lag. Re-link runtime in the browser or re-save status; then `quickjobs sync`.

### Verbose logs

```bash
QUICKJOBS_VERBOSE=1 quickjobs sync
QUICKJOBS_VERBOSE=1 quickjobs run
```

### Scrape stuck or hung

```bash
quickjobs stop
quickjobs status
quickjobs resume    # if checkpoint exists
```

### SSH / sync retries

Sync retries SSH/rsync up to 3 times with DNS IP fallback. If sync fails persistently, check VPN, `~/.ssh/config`, and that wulf is reachable on port 222.

## What not to do

- Do not full-scan `~/Downloads/jobs/job-search-david.html` (~64 MB) with `grep`, `rg`, or unbounded reads. Spot-check with `rg -m 5 'pattern' path` or search Python source instead.
- Do not commit secrets (SSH keys, session cookies, `.wellfound-session.json`) to the repo.
- Do not use port 8765 for casual HTML preview while pipeline autosave may be active.
- Do not edit `quickjobs.david.base.json` on wulf; edit on Mac, validate, then `quickjobs sync`.
- Do not merge pipeline state into `base.json`; runtime lives in the sidecar JSON.
- Do not run `dedup --apply`; it is not implemented.
- Do not skip validation before sync after manual JSON edits.
- For scheduled discovery on Mac, route through `cron-exec` with absolute paths to `~/.v/bin/python`; do not let agents or scripts modify your crontab without your explicit request.
